  • 这张地图就是 data/panorama/domains.yaml 的可视化：5 个业务域 / 8 个能力 / 16 个功能点，接入你们业务时整体替换成自己的域。
  • 功能点的三件套决定了它能不能用：keywords 决定需求匹配得上（越全命中率越高）、implemented_by 决定业务视角能落到系统、锚点决定技术视角能下钻到接口。

附

关键设计决策

决策理由代价与对策
图谱用 YAML 而非图数据库 图谱即代码：改图走 PR、CI 校验，维护贴着研发流程；百级功能点用不上图数据库。 超大规模时再迁移，模型不变。
匹配用关键词打分而非向量/LLM 影响面结论必须可解释：报告列出命中了哪些词，可肉眼复核。 依赖 keywords 质量 → 未命中回补机制兜底；LLM 复核作为二道召回（Roadmap）。
传播有界（业务触发 ≤3 跳；技术调用链 ≤2 跳） 要「值得看一眼的范围」，不是可达性闭包 —— 全图都受影响等于没有结论。 极端长链路可能漏报 → 跳数可配，高关键度节点单独提示。
解构产物是独立 YAML 文件 LLM 产出只是初稿，人工修订后的才是需求资产，随需求归档、可重跑。 多一份文件 → 与需求编号绑定进仓库。
